# SpectraCalc

## Проблематика

В результате процедуры `спектроскопии комбинационного рассеяния` образца по сетке 10\*10 на выходе из прибора мы имеем .zip с `сотней` файлов-записей показаний прибора, в каждом из которых около `3500` пар значений. Для дальнейшей работы необходимо преобразовать такой .zip в heatmap распределения пиков вещества, а также вычислить `среднее`, `σ` и `коэффициент вариации` - с учетом количества данных и необходимой точности расчетов, `вручную такой процесс занимает кучу времени`

`SpectraCalc` берёт такой ZIP и интервал волновых чисел (см⁻¹) и за секунды отдаёт
`тепловую карту распределения`, `PDF-отчёт`, `CSV с матрицей` и `вердикт об однородности` -
через веб-интерфейс

## Принцип работы

1. Каждый из 100 файлов - это спектр (волновое число и интенсивность) в одной точке
   сетки, снятой на поверхности образца
2. В заданном интервале для каждого спектра ищется пик и вычитается локальный фон
3. 100 полученных значений выстраиваются в матрицу 10×10 по номеру файла - так
   плоский список снова становится картой образца
4. По матрице считается статистика (среднее, σ, коэффициент вариации `Sr = σ/μ`) и
   категория однородности: отлично / приемлемо / удовлетворительно / неприемлемо
5. Результат рендерится в тепловую карту (PNG), PDF-отчёт и CSV

## Стек

- **Backend** - TypeScript + NestJS, `@napi-rs/canvas` (рендер PNG), `pdfkit` (PDF),
  `adm-zip`
- **Frontend** - TypeScript + React + Vite, Tailwind

## CI/CD

[`.github/workflows/ci-cd.yml`](.github/workflows/ci-cd.yml):

1. **`check`** - на пуш в любую ветку: линт фронта, проверка типов, тесты и сборка бэка и фронта,
   артефакт с `back/dist` и `front/dist`
2. **`deploy`** - на пуш/мердж в `develop`, если проверки прошли: из артефакта собираются образы
   `spectra-calc-web` и `spectra-calc-back`, проверяются на раннере настоящим расчётом через
   [`docker-compose.yml`](docker-compose.yml), передаются на сервер и запускаются через
   `docker compose up -d --wait`

Для деплоя нужно один раз настроить секреты в Settings → Secrets and variables → Actions → Secrets:

| Секрет            | Значение                                                      |
| ----------------- | ------------------------------------------------------------- |
| `DEPLOY_HOST`     | адрес сервера                                                 |
| `DEPLOY_USER`     | пользователь с доступом к Docker и `/opt/spectra-calc`        |
| `SSH_PRIVATE_KEY` | приватный ключ, публичная часть - в `authorized_keys` сервера |
| `SSH_KNOWN_HOSTS` | вывод `ssh-keyscan <хост>` (сверьте с сервером)               |

И один раз подготовить сервер:

- `/opt/spectra-calc/back.env` - настройки бэка, минимум `PUBLIC_BASE_URL=https://spectra-calc.ru`
  и `ADMIN_PASSWORD=<пароль>` для админки. Деплой его не трогает, а `.env` рядом перезаписывает:
  там только тег образа
- [`nginx.conf`](nginx.conf) - конфиг nginx на сервере, проксирует сайт на `127.0.0.1:8082`

## Админка

`/admin` - вход по паролю из `ADMIN_PASSWORD` в `back.env`. Без пароля админка выключена: её API
отвечает 404, а страница пишет, что пароль не задан.

- **Обзор** - просмотры и уникальные посетители, расчёты (успешные / с ошибкой) по дням за 7, 30
  или 90 дней, популярные страницы, источники переходов, место на диске
- **Расчёты** - каждый загруженный архив: время, IP, параметры, статус и текст ошибки. Из записи
  можно скачать исходный ZIP и открыть результат целиком - тепловую карту, статистику, PNG/PDF/CSV.
  PNG/PDF/CSV собираются заново из сохранённого результата, поэтому работают и после того, как
  публичные копии в `/files` удалены по `STORAGE_TTL_HOURS`
- **Запросы** - лог всех запросов к бэку (`/api`, `/files`) с кодом ответа, временем, размером, IP
  и браузером, плюс сводка по эндпоинтам. Запросы самой админки по умолчанию скрыты

Посещения считает сам сайт: SPA отправляет `sendBeacon` на `/api/track` при смене страницы. Боты,
сама админка и повторный просмотр той же страницы в течение 10 секунд не считаются. Посетитель
определяется хешем IP+браузера, без cookie.

Данные лежат в отдельном томе `data` (`/app/data`): SQLite-база и исходные архивы. В `storage` их
класть нельзя - он целиком раздаётся публично через `/files`. Сроки хранения - `ARCHIVE_TTL_DAYS`
(архивы, по умолчанию 30 дней) и `LOG_RETENTION_DAYS` (логи и посещения, 90 дней). Записи о
расчётах вместе с результатами хранятся бессрочно, это несколько КБ на расчёт.
